What it does

1. A list of filesEach file is a web address plus the place in the lake it should go, for example raw/nndc/…/ENDF-B-VIII.1.tar.gz.
→
2. nsr-fetch downloads themIt runs on an AWS computer in Ohio, the same region as the lake, and downloads each file from the website.
→
3. Into the lakeEach file is written to s3://nsr-lake-613473203863/ at its place in the list.

It answers with one line per file: done, skipped (already in the lake, same size) or error.

The code

lambda_handler

lines 116–127

Runs once per request. It takes the list and handles the files one at a time. A file that fails is marked error and the next one starts.

def lambda_handler(event, context):
    out = []
    for item in event["items"]:
        try:
            out.append(fetch(item, bucket))
        except Exception as e:
            out.append({..., "status": "error", "error": str(e)})
    return out

fetch

lines 56–76

Opens the web address. If the lake already holds a file of the same size at that place, it skips it.

Otherwise it streams the bytes into S3 as they arrive, counts them, and checks the count against the size the website reported.

multipart, upload_parts

lines 79–113

A file over 100 MB is cut into 64 MB pieces. It downloads 8 pieces at a time and retries each up to 4 times. S3 joins the pieces into one file.

If any piece fails, the half-made file is deleted.

ranges = [(n, start, end) for each 64 MB piece]
with ThreadPoolExecutor(8) as ex:
    ex.map(one, ranges)            # GET bytes=start-end → upload_part
s3.complete_multipart_upload(...)
# on any failure: s3.abort_multipart_upload(...)

scripts/nndc/pull.py

on the Mac, for big jobs

Sends 40 files per run, 24 runs at once. A file over 2 GB won't finish in one 15-minute run, so the script opens the upload itself, gives each run 16 pieces (1 GB), and joins them at the end.
