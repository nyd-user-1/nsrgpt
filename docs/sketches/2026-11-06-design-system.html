Rules

  1. Charts fill the whole container. Controls and legends go in the right panel.
  2. No browser dropdowns. Every choice uses the site's menu.
  3. Three pointers: hand on controls, scope on plots, arrow elsewhere.
  4. Header titles are physics names (lib/header-titles.ts). Chart types sit at the frame's foot (lib/viz-charts.ts).
  5. Fraunces for titles only. Body and controls are DM Sans. Figures are mono.
  6. Copy is plain language in the first person singular. No metaphors.
  7. No labels that repeat what the layout already shows.
  8. Port existing code (pax-trinity and others) exactly rather than rebuilding a look-alike.

Proposals — 2026-11-04

4.1 First particle prototype

  1. What it shows: the chart of nuclides as the state of nuclear structure knowledge. Position (N, Z). Elevation/size: count of known levels (ENSDF). Color: years since last evaluation (ENSDF cutoff). Pulse: XUNDL datasets revised this month. Dim marker: nuclides with literature but no evaluation.
  2. Click a nuclide: side panel with its ENSDF levels/half-lives, pending XUNDL datasets, EXFOR entries, recent papers.
  3. Build: R3F + Points + bloom; one committed JSON from nuclide_dict + ensdf_index + xundl_datasets + nsr_nuclides counts; NYSgpt paper tokens for every surface (the design system this sketch ignored).

4.2 Data recommendations per chart — physical quantities only

Sources already parsed and held: AME2020 masses (public/data/ame2020.json), B(E2) tables (be2.json), capture-gamma spectra (capgam/, 38MB), double-beta tables (bbdecay.json), ENSDF decks (levels, Jπ, T½, gammas, decay modes), EXFOR entries, decay_processes Δ vectors.
