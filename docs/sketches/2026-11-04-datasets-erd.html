Reusable tool: ENSDF card parser

A positional decoder for the 80-column card format every NNDC structure dataset uses — ENSDF and XUNDL alike. Written once, now three implementations; reusable for any deck we pull, including the ~88 new XUNDL datasets arriving daily.
ImplementationWhat it emits
nsr/api/_lib/ensdf.ts (173 ln, TypeScript — the reference)Full Dataset object: identification, Q record (Q−, Sₙ, Sₚ, Qα), parents, levels (energy, Jπ, T½) with attached gammas (E, RI, multipolarity, mixing, conversion) and feeds (β/EC/α intensities, log ft), comments and continuations resolved
NYSgpt/scripts/viz-decay-snapshot.mjsGround states only → decay.json (half-lives in seconds, decay modes with branching %)
NYSgpt/scripts/viz-levels-snapshot.mjsLevel schemes → levels.json (139,868 levels, 64,064 gammas with resolved final states)
Format ruleBytes
Nuclide id (NUCID)0–5
Continuation marker (non-blank = continues the record above)5
Comment flag (c / d / t = comment card)6
Record type (L level · G gamma · B/E/A feed · Q q-values · P parent · H history · N normalization)7
Record body (fields at fixed positions per type; e.g. identification card: DSID 9–39, DSREF 39–65, PUB 65–74, date 74–80; Q card: Q− 9–21, Sₙ 21–31, Sₚ 31–41, Qα 41–55)9–80
Continuation fields split on $ and appended to the record above; comments attach to the nearest L/G/feed record—
Reuse candidates: XUNDL archive decks (same format, xundl_archive_datasets.raw), the full ENSDF archive mirror on S3 (every distribution since 2004), monthly refreshes, and any future page that needs levels, gammas, feeds, or Q-values as structured data.
